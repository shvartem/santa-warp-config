# Worker регистрации WARP

Маленький прокси на Cloudflare Workers для кнопки «⚡ Получить конфиг автоматически» на странице.

API регистрации Cloudflare не принимает запросы из браузера (CORS), поэтому страница обращается к этому Worker, а он уже к Cloudflare.

**Как обращаются с ключами:**

- Пара ключей создаётся в браузере пользователя.
- Worker получает **только публичный ключ**, регистрирует его у Cloudflare и возвращает адреса и ключ сервера.
- Приватный ключ не попадает ни в Worker, ни в Cloudflare.

**Защита от злоупотреблений:**

- Worker отвечает только сайтам из `ALLOWED_ORIGINS`.
- Он принимает только запрос регистрации.
- Частота запросов ограничена: не больше 5 в минуту с одного IP и 30 в минуту на весь Worker. Все регистрации идут с адресов Cloudflare Workers, и при большом потоке API может начать отвечать 429.

## Развёртывание

Сейчас Worker развёрнут по адресу **https://damp-bush-c893.shvartem.workers.dev**, и этот адрес прописан в `index.html` (`REGISTER_API_URL`). Если открыть адрес в браузере, Worker ответит, что работает. Сама регистрация идёт через `POST /reg`.

Имя Worker в панели Cloudflare должно совпадать с `name` в `wrangler.toml`.

### Вариант 1: автоматически из GitHub (рекомендуется)

1. Откройте Workers & Pages → `damp-bush-c893` → **Settings → Builds → Connect**.
2. Выберите репозиторий `shvartem/santa-warp-config` и ветку `main`.
3. Укажите **Root directory: `worker`**.

Cloudflare развернёт Worker по `wrangler.toml`, включая лимиты частоты запросов. Дальше каждый мерж в `main` обновляет Worker сам.

### Вариант 2: из терминала

Понадобится Node.js (LTS).

```bash
cd worker
npx wrangler@latest login    # откроется браузер — войдите в аккаунт Cloudflare
npx wrangler@latest deploy
```

### Вариант 3: вручную в панели

Откройте Worker → **Edit code**, замените код содержимым `worker.js` и нажмите **Deploy**.

Учтите два ограничения этого варианта:

- лимитов частоты запросов не будет, они задаются только через `wrangler.toml`;
- после каждого изменения `worker.js` код придётся обновлять вручную.

### Новый Worker с другим адресом

Если вы создаёте новый Worker, поменяйте `name` в `wrangler.toml` и `REGISTER_API_URL` в `index.html`. Если `REGISTER_API_URL` пустой, кнопка на странице скрыта, и остаётся только ручной способ через santa-atmo.ru.

### Проверка

```bash
curl -X POST https://damp-bush-c893.shvartem.workers.dev/reg \
  -H 'Origin: https://shvartem.github.io' \
  -d "{\"key\":\"$(head -c32 /dev/urandom | base64)\"}"
```

Ответ с `"config"` означает, что Worker работает. Сообщение `Cloudflare отказал в регистрации (код 429)` или `403` означает, что API Cloudflare не принимает запросы от Workers. В этом случае остаются скрипт и santa.

## Настройки

В `wrangler.toml`:

- `ALLOWED_ORIGINS` — сайты, которым разрешено обращаться к Worker, через запятую. Для локальной проверки страницы добавьте, например, `http://localhost:8000`.
- `[[ratelimits]]` — лимиты частоты запросов (нужен wrangler 4.36+). Если удалить эти блоки, Worker будет работать без ограничений.
- `CF_API_URL` — адрес API регистрации. По умолчанию он такой же, как в [wgcf](https://github.com/ViRb3/wgcf). Если Cloudflare сменит версию API, обновите `DEFAULT_CF_API_URL` и заголовки в `worker.js` по свежему wgcf.

## Ограничения

С июня 2025 года российские провайдеры ограничивают доступ к сайтам на Cloudflare, включая `*.workers.dev`. Маленькие ответы, как у этого Worker, часто проходят, но надёжность не гарантирована.

Если кнопка не срабатывает, страница предложит получить JSON вручную через santa-atmo.ru.
